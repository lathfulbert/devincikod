Intégration RBAC Unifié + Users Harmonisés
Objectif :
refactorisé et mettre en place un système centralisé et 
modulaire pour la gestion des utilisateurs, rôles et permissions.
Toutes les redondances présentes dans RBAC, ADMIN et AUTH doivent être éliminées.

1. module RBAC
Modèles unifiés
•	Role
•	Permission
•	RolePermission
•	UserRole

Les modèles doivent être les seules sources de vérité pour tout le framework.
1.1 Services
Créer un service RbacService avec les méthodes :
assignRole(User $user, string $role)
removeRole(User $user, string $role)
syncRoles(User $user, array $roles)
hasRole(User $user, string $role): bool

givePermissionToRole(string $role, string $permission)
roleHasPermission(string $role, string $permission): bool
userHasPermission(User $user, string $permission): bool
1.2 Middlewares
Créer :
•	CheckRole
•	CheckPermission
•	CheckAnyPermission
Fonctionnement :
•	unified guard system
•	utilisable dans web.php, api.php, routes versionnées v1/v2…
1.3 Loader modulaire automatique
Chaque module peut déclarer des permissions via un fichier :
modules/<module>/config/permissions.php
Core RBAC :
•	scan automatique des modules
•	charge toutes les permissions
•	seed automatiques depuis un seul point


1.4 Config
Créer config/rbac.php :
return [
   'permissions_cache' => true,
   'default_roles' => ['admin', 'user'],
];

3. Interfaces contractuelles (découplage total)
Créer dans core/contracts/ :
UserProviderInterface
RbacProviderInterface
Admin, Auth, API, Modules externes doivent utiliser ces interfaces, jamais directement les classes internes.


2. Module ADMIN
•	Retirer modèles User, Role, Permission existants → utiliser Core

3. Module AUTH
