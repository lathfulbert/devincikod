Je veux intégrer un mécanisme de Job Queue + Cron Scheduler dans le Core de mon framework (Framework LathDevinci).

Le résultat attendu est un module de base du Core, extensible par les modules externes (plugins), et respectant un contrat standard commun à tous les modules.

🎯 Objectif

Construire un système de traitement asynchrone :

exécution de jobs en arrière-plan (Queue)

un scheduler interne pour tâches périodiques (Cron)

adaptable à plusieurs drivers : database, Redis, file-system

API accessible via HTTP et plus tard via un gateway ou microservice

architecture claire, découplée et propre

🔧 Ce que tu dois générer
1. Structure complète du module Core Queue

Dossier

Fichiers

Interfaces

Services

Drivers (database, redis, file)

Worker CLI (ex : php artisan queue:work ou nest start worker)

Contrat pour les modules externes : JobContract, QueueDriverContract, QueueManager

2. Structure complète du module Core Cron

scheduler

table de crons

exécution sous forme de tâches asynchrones

mapping entre modules et leurs crons

Cron expression parser

Worker dédié : cron:run

3. Un contrat standard pour les modules externes

Exemple :

chaque module peut déclarer :

ses jobs (ModuleName/Jobs/MyJob)

ses crons (ModuleName/Cron/DailyTask)

format YAML ou JSON pour déclarer les tâches

système d’enregistrement automatique dans le Core

4. Un système de configuration

fichier config : queue.php et cron.php

choix du driver

connection redis

nombre de workers

retry, timeout, backoff

5. Un CRUD minimal pour le backoffice

voir la liste des jobs

consulter les échecs (failed_jobs)

relancer un job

logs

6. Exemples complets

créer un job (send email, generate PDF)

ajouter une tâche cron (chaque minute, chaque jour)

résultat en TypeScript ou PHP selon besoin

avec dépendance injection

7. Bonne pratique

architecture inspirée de Laravel Queue, NestJS Schedule, BullMQ, Symfony Messenger

système modulaire, extensible, indépendant du Core

propre, documenté, compatible future API Gateway

Produit-moi :

La documentation complète (markdown téléchargeable)

Le code source complet du module (core/queue + core/cron)

Les interfaces standards que tous les modules devront respecter

Un exemple d’intégration dans un module externe (ex : Module Blog)

La commande CLI pour lancer workers et cron scheduler
