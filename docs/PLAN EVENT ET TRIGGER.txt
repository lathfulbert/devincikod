Core Components
1. Event Base Class
File: Core/Events/Event.php

abstract class Event
{
    protected array $data = [];
    protected bool $propagationStopped = false;
    
    public function stopPropagation(): void
    public function isPropagationStopped(): bool
    public static function dispatch(...$args): void
}
2. EventDispatcher
File: Core/Events/EventDispatcher.php

class EventDispatcher
{
    public function dispatch(object $event): object
    public function listen(string $event, $listener): void
    public function hasListeners(string $event): bool
    public function getListeners(string $event): array
    protected function callListener($listener, $event): mixed
}
3. Listener Interface
File: Core/Contracts/ListenerInterface.php

interface ListenerInterface
{
    public function handle(object $event): void;
}
4. Queued Listener Support
File: Core/Contracts/ShouldQueue.php

interface ShouldQueue
{
    public function queue(): string; // Queue name
    public function delay(): int;    // Delay in seconds
}
Module Integration
events.php Configuration
Each module can register events via Modules/{Module}/events.php:

return [
    // Event class => [Listeners]
    \Modules\Auth\Events\UserRegistered::class => [
        \Modules\Auth\Listeners\SendWelcomeEmail::class,
        \Modules\Stats\Listeners\TrackNewUser::class,
    ],
    
    \Modules\Blog\Events\PostCreated::class => [
        \Modules\Blog\Listeners\NotifySubscribers::class,
        \Modules\Search\Listeners\IndexPost::class,
    ],
];

Usage Examples
1. Simple Synchronous Event
// Dispatch event
use Modules\Blog\Events\PostCreated;
PostCreated::dispatch($post);
// Listener
class NotifySubscribers implements ListenerInterface
{
    public function handle(object $event): void
    {
        $post = $event->post;
        // Send notifications...
    }
}
2. Queued Async Event
class SendWelcomeEmail implements ListenerInterface, ShouldQueue
{
    public function handle(object $event): void
    {
        // Send email...
    }
    
    public function queue(): string
    {
        return 'emails';
    }
    
    public function delay(): int
    {
        return 0;
    }
}
3. Stop Propagation
class CheckUserBanned implements ListenerInterface
{
    public function handle(object $event): void
    {
        if ($event->user->isBanned()) {
            $event->stopPropagation();
        }
    }
}
Integration with Existing Systems
Queue Integration
Listeners implementing 
ShouldQueue
 are automatically pushed to the queue system:

QueueManager::push(
    \App\Jobs\CallQueuedListener::class,
    ['listener' => $listenerClass, 'event' => serialize($event)],
    $listener->queue()
);
Cron Integration
Events can be dispatched from cron tasks:

class DailyReportTask extends CronTask
{
    public function handle(): void
    {
        DailyReportGenerated::dispatch($report);
    }
}
Module Activation
When modules are activated/deactivated, their events are registered/unregistered automatically.

Performance Considerations
Lazy loading: Listeners instantiated only when event fires
Caching: Event-to-listener mapping cached in production
Async by default: Heavy listeners should implement 
ShouldQueue
Singleton dispatcher: Single instance shared across app
Future Enhancements
Event Priority: Execute listeners in specific order
Wildcard Listeners: Listen to multiple events with patterns
Redis Pub/Sub: Distributed event system across servers
Event Replay: Store events for debugging/replay
Conditional Listeners: Only fire if conditions met
